Server-Side vs Pixel: Where Event Match Quality Really Comes From

Оновлено 6 November 2026 · Business Ads Guide

What match quality measures

Event match quality scores how well the identifiers you send can be tied to a real TikTok user. It is a function of coverage — how many identifiers you send — and accuracy — whether those identifiers are correct and consistently formatted. Moving the same thin payload from browser to server changes nothing about either.

The identifiers that matter

Email, phone, external ID, IP address, user agent, and click ID. Email and phone are the strongest; both should be normalized (lowercase, trimmed, E.164 for phone) and hashed with SHA-256 before transmission. A common failure is sending a phone number with spaces or a leading zero, which hashes into a value that matches nothing.

Why server-side helps anyway

Not because of match quality per se, but because of durability. Browser events get lost to ad blockers, ITP, and page abandonment. A server event fired from your backend after the order is confirmed survives all three. The gain is in event completeness, particularly for purchase events fired after a redirect.

The duplication trap

Running pixel and server events without a shared event ID produces double counting, which inflates reported conversions and teaches the algorithm to over-deliver to users who were never going to convert twice. Always send the same event_id from both sources so the platform can deduplicate.
